## Project Overview

This is an **Obsidian plugin** (desktop-only) for managing APP version planning and associated projects. The UI is Chinese-language. Data is stored as markdown files with YAML frontmatter.

## Build Commands

```bash
# Development (watch mode)
npm run dev

# Production build (type-check + bundle)
npm run build

# Deploy to local Obsidian plugin directory (Windows path hardcoded in package.json)
npm run deploy
```

- Bundled output: `main.js` (generated by esbuild from `src/main.ts`)
- Required for Obsidian: `main.js` + `manifest.json`
- No test runner, linter, or formatter is configured.

## Architecture

### Plugin Entry Point

`src/main.ts` — registers the custom view (`AppVersionManagerView`), commands, settings tab, and injects all CSS as an inline `<style>` tag (`STYLE_ID`).

### Data Model (hierarchical)

- **App** → contains multiple **Version** → contains multiple **Project**
- **Plan** — lightweight planning entries that can be converted to Projects
- **Memo** — per-project free-text notes, stored separately from project config

All entities have an `id` (UUID), `version` (optimistic concurrency number), and timestamps.

### Data Persistence

`src/services/DataService.ts` is the single source of truth for all file I/O:

- Stores data as markdown files with YAML frontmatter in folders under `app-version-manager/` (default), or a user-configured path.
- **Supports both vault-relative paths** (via Obsidian `vault` API) **and absolute filesystem paths** (via Node `fs` API). Every read/write path checks `isAbsolutePath()` and branches accordingly.
- Uses a **custom frontmatter parser** (`parseFrontmatter`) — not Obsidian's metadata cache. The parser handles strings, booleans, nulls, arrays, and multiline strings (`|`).
- Has a simple **in-memory cache with 5-second TTL** (`DataCache`). Call `this.cache.invalidate(key)` after mutations.
- Files are named like `{sanitizedName}__{id}.md` (double-underscore separator).

### View Layer

`src/view/AppVersionManagerView.ts` is the main view. It renders a header (app selector, view switcher, filters) and delegates to one of four sub-views:

| View | File | Description |
|------|------|-------------|
| Dual Pane | `DualPaneView.ts` | Left: version list; Right: project cards for selected version |
| Kanban | `KanbanView.ts` | Columns by progress stage |
| Table | `TableView.ts` | Tabular view; clicking progress badge advances to next stage |
| Gantt | `GanttView.ts` | Timeline view (appears to be a newer addition) |

All views receive data arrays and a `onRefresh` callback. They do not hold state across renders; the parent view re-creates them on every refresh.

### Business Logic

- **Progress stages** are user-configurable in settings (default: 7 stages from 需求分解 to 已发布). Colors and names are editable. Many helpers live in `src/types.ts` (`getProgressOrder`, `getProgressColors`, etc.).
- **Project sorting** (`src/utils/projectSorting.ts`): Projects are sorted by urgency of next test-stage date. Today = priority 1, tomorrow = priority 2, future = priority 3, no date = priority 4, released = priority 5 (always last).
- **Overdue/highlight logic**: A project is "highlighted" (red border) if its next stage date is today or within the warning window. It is "overdue" (red background) if the date has passed.
- **Test stages**: Each project has 8 test-plan date fields (B1–B4 × integration/system test). The next upcoming date drives sorting and highlighting.

### Services

- `DataService` — CRUD for Apps, Versions, Projects, Plans; file I/O; caching.
- `ImportExportService` — CSV/Excel/JSON import and export. Uses dynamic import of `xlsx` for Excel.
- `BackupService` — Scheduled weekly backups to JSON files in `app-version-manager/backups/` (or custom path). Keeps last 10 backups. Supports restore with rollback on failure.

### Settings

Stored via Obsidian's `loadData`/`saveData`. Key fields:
- `dataPath` — root folder for all data (default: `app-version-manager`)
- `backupPath` — backup folder override
- `progressStages` — array of `{name, color}` defining workflow stages
- `overdueWarningDays` — how many days before a deadline to start highlighting

### Important Conventions

- **Concurrency control**: Updates accept an optional `expectedVersion`. If the entity's `version` field has changed, a `ConcurrencyConflictError` is thrown.
- **Null safety**: The codebase recently had fixes for undefined fields becoming `undefined` in frontmatter. Empty string `''` is the preferred "no value" representation for optional string fields; use `|| ''` when constructing frontmatter objects.
- **Modal buttons**: The convention is "confirm on the left, cancel on the right". Use `createActionButtons` or `createSaveButtons` from `ModalUtils.ts` for consistency.
- **Date parsing**: `parseDateInput` in `types.ts` supports multiple Chinese formats plus `MM.DD` (auto-current-year). Use it for all user-facing date inputs.
- **Progress history**: Stored as strings like `"stageName@timestamp"` in frontmatter, parsed into `ProgressHistoryItem[]`.
